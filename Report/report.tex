\begin{abstract}
This report presents a hybrid MPI+OpenCilk parallel algorithm for computing connected components in large sparse graphs. We describe the algorithm, key optimizations (asynchronous communication, edge-balanced partitioning), and present performance results showing 2.5x speedup with asynchronous BFS.
\end{abstract}

% ------------------------------------------------------------------------------
% Section 1: Introduction
% ------------------------------------------------------------------------------
\section{Introduction}

Finding connected components in large graphs is a fundamental problem in graph analytics with applications in social network analysis, image processing, and scientific computing. As graph sizes grow to billions of edges, parallel algorithms become essential for practical computation times.

This project implements a parallel connected components algorithm using:
\begin{itemize}
    \item \textbf{MPI} (Message Passing Interface) for distributed memory parallelism across cluster nodes.
    \item \textbf{OpenCilk} for shared memory parallelism within each node using work-stealing.
\end{itemize}

The input graphs are stored in MATLAB's \texttt{.mat} format and converted to Compressed Sparse Row (CSR) format for efficient traversal.

% ------------------------------------------------------------------------------
% Section 2: Algorithm Design
% ------------------------------------------------------------------------------
\section{Algorithm Design}

\subsection{Graph Representation}

The input graph is stored using the Compressed Sparse Row (CSR) format, consisting of the arrays \texttt{row\_ptr[n+1]} and \texttt{col\_idx[m]}, where \texttt{row\_ptr} defines the adjacency list boundaries and \texttt{col\_idx} stores destination vertices. This representation provides $O(1)$ neighbor access, good cache locality, and is well suited for large sparse graphs. CSR is also convenient for distributed memory, since vertex ranges can be cleanly partitioned across MPI ranks while keeping adjacency lists contiguous in memory.

\subsection{Label Propagation Algorithm}

Connected components are computed using an iterative label propagation approach. Initially, each vertex is assigned its own global ID as a label. At each iteration, vertices propagate the minimum label among their neighbors, and the process repeats until no labels change. This algorithm is simple, scalable, and works well on large real-world graphs. Convergence is guaranteed when a global iteration completes with no further label updates.

\subsection{Parallelization Strategy}

\paragraph{MPI-based graph partitioning.}
The graph is distributed across MPI ranks by assigning each process a contiguous range of global vertices $[vtx\_dist[rank], vtx\_dist[rank+1])$. This distribution is computed during initialization using a block-based (edge-aware) partitioning strategy implemented in \texttt{partition.c}. During execution, ownership of a global vertex is determined using the \texttt{get\_owner()} function, which performs a binary search on the \texttt{vtx\_dist} array (see \texttt{BFSmpi.c}). This allows each rank to distinguish between local and remote vertices efficiently.

\paragraph{Local computation with OpenCilk.}
Within each MPI rank, shared-memory parallelism is exploited using OpenCilk. Vertex processing loops are parallelized with \texttt{cilk\_for}, allowing efficient load balancing via work-stealing. This hybrid MPI + OpenCilk model enables parallelism both across nodes (distributed memory) and within nodes (shared memory).

\paragraph{Inter-rank communication.}
Since MPI ranks do not share memory, label updates involving remote vertices must be explicitly communicated. When a rank encounters an edge whose destination vertex belongs to another rank, the update is packed into a send buffer. Communication follows a standard MPI two-phase pattern: \texttt{MPI\_Alltoall} is used to exchange message sizes, and \texttt{MPI\_Alltoallv} is then used to exchange the actual variable-sized buffers containing pairs of (vertex, label). This explicit message passing is a fundamental difference from the shared-memory approach used in HW1.

\paragraph{Global convergence detection.}
Termination cannot be decided locally. In the frontier-based BFS variant, convergence is detected when the global frontier size becomes zero, computed using \texttt{MPI\_Allreduce} with a SUM operation across all ranks. In the asynchronous variant, a quiescence detection mechanism is implemented by tracking globally sent and received messages and using non-blocking collective operations (\texttt{MPI\_Iallreduce}) while continuing to poll for incoming updates.

\section{Optimizations}

\subsection{Binary CSR Caching}
We cache converted graphs as \texttt{.csrbin} files, reducing load times from minutes to seconds.

\subsection{Graph Preprocessing}
\textbf{Symmetrization} ensures undirected graphs; \textbf{degree-based reordering} improves cache locality.

\subsection{Edge-Balanced Partitioning}
Instead of simple vertex-block distribution, we balance edges per MPI rank, significantly improving load balance for scale-free graphs.

\subsection{Asynchronous BFS}
Our asynchronous variant overlaps computation with communication using double-buffered \texttt{MPI\_Isend}, polls for messages during local propagation, and uses quiescence-based termination. This achieves \textbf{2.5x speedup} over synchronous.

\subsection{64-bit Indexing}
To support graphs with >2.14B edges, we use 64-bit \texttt{long long} for edge counts and row pointers.

\subsection{Analysis}

\subsubsection{Async Speedup}
The asynchronous algorithm achieves \textbf{1.56x speedup} over the sequential baseline (7.56s $\rightarrow$ 4.84s) by overlapping computation with communication.

\subsubsection{PGO Impact}
Profile-Guided Optimization reduced iterations from 4.3M to 3.1M through better branch prediction, but the final time (5.63s) is slightly higher than the non-PGO async run (4.84s). This is attributed to cluster load conditions: the PGO tests (test10, test11) were executed on a day when the cluster was significantly more overloaded, causing all builds and runs to complete slower than usual.

\textbf{Analysis:}
The local workstation (Ryzen 7 5800H, 32GB RAM, ~20GB used) significantly outperforms the cluster for this specific workload.
\begin{itemize}
    \item \textbf{Local Speedup}: The shared-memory Cilk implementation (Label Propagation) running on a single consumer node completes in \textbf{1.30s}, which is \textbf{23x faster} than the best distributed run on the cluster (29.86s).
    \item \textbf{Overhead}: The cluster performance is dominated by the overhead of the distributed Frontier BFS algorithm (partitioning, communication, message packing) which is necessary for scaling to multi-terabyte graphs but inefficient for graphs that fit in a single node's RAM relative to a zero-overhead shared-memory approach.
    \item \textbf{Sequential Baseline}: The cluster sequential baseline (74.94s) highlights the significant cost of the distributed data structures even when running on a single rank, compared to the optimized local execution.
\end{itemize}

\section{Conclusion}

We implemented a hybrid MPI+OpenCilk parallel connected components algorithm with:
\begin{itemize}
    \item Binary CSR caching for fast graph loading
    \item \textbf{Asynchronous BFS} providing 1.56x speedup over sequential
    \item Edge-balanced partitioning for scale-free graphs
    \item 64-bit indexing for billion-edge graphs
\end{itemize}
